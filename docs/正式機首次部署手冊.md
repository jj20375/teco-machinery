# 正式機首次部署手冊（Windows Hyper-V → Ubuntu VM → Docker）

第一次在現場 Windows 主機上建置整套服務，並把開發機（Mac）上的資料庫設定搬過去。
部署完成後，現場接通驗證接著看 [`IOT_現場接通驗證手冊.md`](IOT_現場接通驗證手冊.md)。

> ⚠️ 這份流程裡 Hyper-V 與 VM 的部分（第 1、2 步）**還沒有在真的現場主機上跑過**。
> 第 6 步「全新資料庫初始化 → 匯入設定資料」已經在本機用拋棄式容器實際演練成功（2026-09-29）。

整體架構：

```
Windows 主機（Hyper-V）
└─ Ubuntu Server 24.04 VM（192.168.10.200）
   └─ Docker Engine
      ├─ web       Caddy：網站＋/api、/hubs 反代      → 對區網開 8081
      ├─ api       ASP.NET Core API＋排程              → 只綁 127.0.0.1:8082
      ├─ collector 讀現場 Modbus 設備                  → 不開 port
      └─ mariadb   資料庫                              → 只綁 127.0.0.1:3307
```

---

## 第 1 步：Windows 建 VM

照 [`backend/deploy/host-setup/01-hyperv-vm-setup.md`](../backend/deploy/host-setup/01-hyperv-vm-setup.md)：
啟用 Hyper-V → 建 External vSwitch → 建 Ubuntu 24.04 VM → 設定靜態 IP。
本手冊以 VM IP `192.168.10.200`、使用者 `teco` 為例，實際值不同就自行替換。

完成後在 VM 內確認能 ping 到三台設備（Gateway、DDC1、DDC2）。

## 第 2 步：VM 安裝 Docker

**先放 SSH 公鑰，再跑安裝腳本**（腳本會關掉 SSH 密碼登入；沒偵測到公鑰時會跳過這一步並提醒）。

在 Mac 上執行：

```bash
ssh-copy-id teco@192.168.10.200
```

```bash
scp backend/deploy/host-setup/02-ubuntu-docker-setup.sh teco@192.168.10.200:~/
```

在 VM 上執行：

```bash
bash ~/02-ubuntu-docker-setup.sh
```

跑完**登出再登入一次**，`docker` 群組權限才會生效。確認：

```bash
docker compose version
```

## 第 3 步：Mac 上準備檔案

### 3.1 建置前端

網站容器直接掛載專案根目錄的 `dist/`，所以要先在 Mac 建好：

```bash
npm run build
```

### 3.2 匯出資料庫

**建議只帶設定類資料**：帳號、角色、場館、設備主檔、客戶自訂代碼、圖面配置、告警門檻、操作紀錄。

時序資料不帶，原因是開發機上的時序資料沒有保留價值：

- `fcu_reading`、`chiller_reading` 絕大部分是設備斷線時寫入的 0 值資料（`read_status=3`）
- 報表用的每小時聚合是 `seed-demo-data.sh` 產生的假資料
- `alarm_event` 是模擬告警

```bash
cd backend/deploy && source .env && docker compose exec -T mariadb mariadb-dump -u root -p"$DB_ROOT_PASSWORD" --single-transaction --routines --triggers --ignore-table=teco_hvac.fcu_reading --ignore-table=teco_hvac.chiller_reading --ignore-table=teco_hvac.channel_health --ignore-table=teco_hvac.rollup_fcu_1h --ignore-table=teco_hvac.rollup_chiller_1h --ignore-table=teco_hvac.alarm_event --ignore-table=teco_hvac.refresh_token teco_hvac > ~/teco_hvac_config.sql
```

如果確定要整個資料庫原封不動搬過去，就把所有 `--ignore-table=...` 拿掉。

⚠️ 搬過去的 `device_fcu.zone_code` 仍然是**驗收用的模擬分區對照**，交機前要在「空間設備配置」頁重新拖拉、存檔覆蓋掉。

### 3.3 同步專案到 VM

以下檔案不同步：依賴套件、編譯產物、`.git`、開發機的 `.env`（VM 要用自己的密碼），以及含明文密碼的 `docs/工作站主機資料.md`。

```bash
rsync -av --exclude node_modules --exclude 'bin/' --exclude 'obj/' --exclude .git --exclude 'backend/deploy/.env' --exclude 'docs/工作站主機資料.md' ./ teco@192.168.10.200:~/teco/
```

```bash
scp ~/teco_hvac_config.sql teco@192.168.10.200:~/
```

如果 Mac 連不到 VM 的網段，先把專案資料夾和 `.sql` 檔複製到 Windows 主機，再從 Windows 的 PowerShell 用 `scp` 傳進 VM（Windows 10 以上內建 OpenSSH）。

> **為什麼不用 `docker context` 從 Mac 遠端部署？** `compose.yaml` 的 bind mount
> （`./mariadb/init`、`./Caddyfile`、`../../dist`）會被當成 VM 上的路徑去找，VM 上沒有就會掛到空資料夾。
> 結果是資料庫沒有初始化、網站起不來。所以一定要先把檔案同步到 VM，再在 VM 上執行。

## 第 4 步：VM 上建立 `.env`

```bash
cd ~/teco/backend/deploy && cp .env.example .env
```

四個密碼欄位（`DB_ROOT_PASSWORD`、`DB_APP_PASSWORD`、`INTERNAL_TOKEN`、`JWT_SIGNING_KEY`）都填入新產生的隨機值，**不要沿用開發機的密碼**。每個欄位各執行一次：

```bash
openssl rand -hex 32
```

同一個檔案裡，`HANBELL_IP`、`DDC1_IP`、`DDC2_IP`（以及 Port）改成現場的真實位址。`FRONTEND_ORIGIN` 維持預設即可：網站跟 API 經過同一個 Caddy，屬於同源，不會觸發 CORS。

把 `.env` 權限收緊，只有自己能讀：

```bash
chmod 600 .env
```

## 第 5 步：限制網站連線來源（建議）

網站對區網開放 8081，其中**前台戰情室不用登入**。如果現場區網有不相干的設備或訪客，用防火牆限制只允許維運網段連入。網段請依現場實際情況調整：

```bash
sudo ufw allow OpenSSH
```

```bash
sudo ufw allow from 192.168.50.0/24 to any port 8081 proto tcp
```

```bash
sudo ufw enable
```

⚠️ 一定要**先**加 `OpenSSH` 那條規則，再執行 `ufw enable`，不然 SSH 會被擋掉。

另外注意：Docker 發布的 port 會繞過 ufw 的部分規則。要確認限制真的生效，就從不在允許網段的電腦試連一次。

## 第 6 步：起資料庫 → 匯入 → 起全部服務

**順序很重要**：資料要在 API 與 Collector 啟動**之前**匯入，避免邊寫邊被覆蓋。

### 6.1 只啟動資料庫

```bash
cd ~/teco/backend/deploy && docker compose up -d mariadb
```

第一次啟動會自動執行 `mariadb/init/` 裡的全部腳本（建帳號、建表、初始資料、權限 migration），大約 30 秒。等狀態變成 `healthy`：

```bash
docker compose ps
```

### 6.2 匯入設定資料

dump 裡每張表都有 `DROP TABLE` 再重建，所以會把初始資料換成開發機的設定。沒有匯出的時序表則維持初始化建立的空表，分割區是完整的。

```bash
source .env && docker compose exec -T mariadb mariadb -u root -p"$DB_ROOT_PASSWORD" teco_hvac < ~/teco_hvac_config.sql
```

確認資料有進去：

```bash
source .env && docker compose exec -T mariadb mariadb -u root -p"$DB_ROOT_PASSWORD" teco_hvac -e "SELECT COUNT(*) AS users FROM app_user; SELECT COUNT(*) AS fcu FROM device_fcu; SELECT COUNT(*) AS placements FROM device_floor_placement;"
```

### 6.3 啟動全部服務

第一次會在 VM 上編譯 API 與 Collector 的映像檔，要花幾分鐘：

```bash
docker compose up -d --build
```

## 第 7 步：驗證

1. 四個服務都是 `running`，並且 `mariadb`、`api`、`collector` 是 `healthy`：

```bash
docker compose ps
```

2. 在 VM 上確認 API 就緒：

```bash
curl -s http://localhost:8082/readyz
```

3. 從 **Windows 主機的瀏覽器**打開 `http://192.168.10.200:8081`，前台戰情室應該會出現。打不開的話：
   - 確認 `compose.yaml` 的 `web` ports 是 `"8081:80"`，不是 `127.0.0.1:8081:80`
   - 檢查第 5 步的 ufw 規則

4. 用原本的帳號登入。帳號資料已經搬過來，所以**密碼跟開發機相同**。`JWT_SIGNING_KEY` 換了，所有人都需要重新登入，這是正常的。

5. 用平台帳號打開 **系統診斷**（`/platform/diagnostics`），接著照 [`IOT_現場接通驗證手冊.md`](IOT_現場接通驗證手冊.md) 檢查三條通道。

6. 設定 VM 每日備份，見 `backend/deploy/host-setup/03-docker-context-from-mac.md` §3.5。

## 之後更新程式

在 Mac 上執行：

```bash
npm run build
```

```bash
rsync -av --delete --exclude node_modules --exclude 'bin/' --exclude 'obj/' --exclude .git --exclude 'backend/deploy/.env' --exclude 'docs/工作站主機資料.md' ./ teco@192.168.10.200:~/teco/
```

在 VM 上執行：

```bash
cd ~/teco/backend/deploy && docker compose up -d --build
```

注意事項：

- `--delete` 讓 VM 跟 Mac 保持一致；被 `--exclude` 的 `.env` 不會被刪掉。
- **新增的 `mariadb/init/0xx_*.sql` 不會自動套用到已經在跑的資料庫**（init 腳本只在資料庫第一次建立時執行）。每次更新時看一下有沒有新的 migration 檔，有的話手動執行：

```bash
source .env && docker compose exec -T mariadb mariadb -u root -p"$DB_ROOT_PASSWORD" < mariadb/init/0xx_新的檔案.sql
```

- 更新前先備份一次資料庫（§3.5 的指令手動執行一次即可）。

## 出問題要重來

**第一次部署失敗、想整個重建時**，下面這個指令會刪掉資料庫 volume，**資料會全部消失**，只能在還沒有正式資料時使用：

```bash
docker compose down -v
```

刪掉之後，從第 6 步重新開始。

已經有正式資料之後，不要再使用 `down -v`。要還原就用備份檔（見 §3.5 的還原指令）。
