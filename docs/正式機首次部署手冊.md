# 正式機首次部署手冊（Windows Hyper-V → Ubuntu VM → Docker）

第一次在現場 Windows 主機上建置整套服務，並把開發機（Mac）上的資料庫設定搬過去。
部署完成後，現場接通驗證接著看 [`IOT_現場接通驗證手冊.md`](IOT_現場接通驗證手冊.md)。

> ⚠️ 這份流程裡 Hyper-V 與 VM 的部分（第 1、2 步）**只有部分在真的現場主機上驗證過**：
> Windows 主機的 OpenSSH、Tailscale、VM 的 Tailscale 與 SSH 連線已實際連通（2026-09-29）；
> **External 交換器與固定 IP（附錄 B）尚未實作**，目前 VM 還在 Default Switch（NAT）。
> 第 6 步「全新資料庫初始化 → 匯入設定資料」已經在本機用拋棄式容器實際演練成功（2026-09-29）。

## 連線名稱約定

本手冊的 SSH 指令都用 `~/.ssh/config` 裡的主機別名，設定方式見**附錄 A**：

| 別名 | 指向 | 用途 |
|---|---|---|
| `teco-win-tailscale` | Windows 主機（Tailscale 位址） | 管理 Hyper-V、開關 VM |
| `teco-vm-tailscale` | Ubuntu VM（Tailscale 位址） | **日常使用**：部署、看 log、資料庫 |

VM 的區網 IP 會隨網路架構而變（目前是 Default Switch 的 NAT 位址，重開機可能改變），
所以日常一律用 Tailscale 別名，不要寫死 IP。VM 使用者名稱依你安裝 Ubuntu 時設定的為準
（本專案現況是 `emmt-teco-project`，下文範例的 `~/teco/` 都是 VM 使用者家目錄底下）。

整體架構：

```
Windows 主機（Hyper-V）
└─ Ubuntu VM（Ubuntu Desktop 24.04；正式機建議 Server 版，省記憶體）
   └─ Docker Engine
      ├─ web       Caddy：網站＋/api、/hubs 反代      → 對區網開 8081
      ├─ api       ASP.NET Core API＋排程              → 只綁 127.0.0.1:8082
      ├─ collector 讀現場 Modbus 設備                  → 不開 port
      └─ mariadb   資料庫                              → 只綁 127.0.0.1:3307
```

## 第 1 步：Windows 建 VM

照 [`backend/deploy/host-setup/01-hyperv-vm-setup.md`](../backend/deploy/host-setup/01-hyperv-vm-setup.md)：
啟用 Hyper-V → 建 Ubuntu 24.04 VM。網路有兩種階段：

- **先用 Default Switch（NAT）**：VM 能上網、Windows 主機連得到 VM，足夠先完成第 2～7 步，
  確認 API、網站、資料庫、系統診斷頁都正常。**但 VM 不在現場設備網段**，Collector 連不到設備。
  IP 也不固定，不要在 VM 裡手動設固定 IP（見附錄 B 的說明）。
- **接設備前改成 External 交換器並固定 IP**：見**附錄 B**。

⚠️ Ubuntu Desktop 預設**沒有 SSH 伺服器**，要先在 VM 裡安裝並啟動：

```bash
sudo apt update && sudo apt install -y openssh-server
```

```bash
sudo systemctl enable --now ssh
```

先完成**附錄 A**（遠端連線），再往下做。

## 第 2 步：VM 安裝 Docker

**先放 SSH 公鑰，再跑安裝腳本**（腳本會關掉 SSH 密碼登入；沒偵測到公鑰時會跳過這一步並提醒）。

公鑰已經在附錄 A 放好的話，這裡不用再做。在 Mac 上執行：

```bash
scp backend/deploy/host-setup/02-ubuntu-docker-setup.sh teco-vm-tailscale:~/
```

（如果 VM 上已經裝過 Docker，可以跳過這個腳本，用 `docker compose version` 確認即可。）

在 VM 上執行：

```bash
bash ~/02-ubuntu-docker-setup.sh
```

跑完**登出再登入一次**，`docker` 群組權限才會生效。確認：

```bash
docker compose version
```

## 第 3 步：Mac 上準備檔案

### 3.1 建置前端

網站容器直接掛載專案根目錄的 `dist/`，所以要先在 Mac 建好：

```bash
npm run build
```

### 3.2 匯出資料庫

**建議只帶設定類資料**：帳號、角色、場館、設備主檔、客戶自訂代碼、圖面配置、告警門檻、操作紀錄。

時序資料不帶，原因是開發機上的時序資料沒有保留價值：

- `fcu_reading`、`chiller_reading` 絕大部分是設備斷線時寫入的 0 值資料（`read_status=3`）
- 報表用的每小時聚合是 `seed-demo-data.sh` 產生的假資料
- `alarm_event` 是模擬告警

```bash
cd backend/deploy && source .env && docker compose exec -T mariadb mariadb-dump -u root -p"$DB_ROOT_PASSWORD" --single-transaction --routines --triggers --ignore-table=teco_hvac.fcu_reading --ignore-table=teco_hvac.chiller_reading --ignore-table=teco_hvac.channel_health --ignore-table=teco_hvac.rollup_fcu_1h --ignore-table=teco_hvac.rollup_chiller_1h --ignore-table=teco_hvac.alarm_event --ignore-table=teco_hvac.refresh_token teco_hvac > ~/teco_hvac_config.sql
```

如果確定要整個資料庫原封不動搬過去，就把所有 `--ignore-table=...` 拿掉。

⚠️ 搬過去的 `device_fcu.zone_code` 仍然是**驗收用的模擬分區對照**，交機前要在「空間設備配置」頁重新拖拉、存檔覆蓋掉。

### 3.3 同步專案到 VM

以下檔案不同步：依賴套件、編譯產物、`.git`、開發機的 `.env`（VM 要用自己的密碼），以及含明文密碼的 `docs/工作站主機資料.md`。

```bash
rsync -av --exclude node_modules --exclude 'bin/' --exclude 'obj/' --exclude .git --exclude 'backend/deploy/.env' --exclude 'docs/工作站主機資料.md' ./ teco-vm-tailscale:~/teco/
```

```bash
scp ~/teco_hvac_config.sql teco-vm-tailscale:~/
```

Mac 連不到 VM 時，先確認 Tailscale 兩邊都在線（`tailscale status`），細節見附錄 A 的排查表。

> **為什麼不用 `docker context` 從 Mac 遠端部署？** `compose.yaml` 的 bind mount
> （`./mariadb/init`、`./Caddyfile`、`../../dist`）會被當成 VM 上的路徑去找，VM 上沒有就會掛到空資料夾。
> 結果是資料庫沒有初始化、網站起不來。所以一定要先把檔案同步到 VM，再在 VM 上執行。

## 第 4 步：VM 上建立 `.env`

```bash
cd ~/teco/backend/deploy && cp .env.example .env
```

四個密碼欄位（`DB_ROOT_PASSWORD`、`DB_APP_PASSWORD`、`INTERNAL_TOKEN`、`JWT_SIGNING_KEY`）都填入新產生的隨機值，**不要沿用開發機的密碼**。每個欄位各執行一次：

```bash
openssl rand -hex 32
```

同一個檔案裡，`HANBELL_IP`、`DDC1_IP`、`DDC2_IP`（以及 Port）改成現場的真實位址。`FRONTEND_ORIGIN` 維持預設即可：網站跟 API 經過同一個 Caddy，屬於同源，不會觸發 CORS。

把 `.env` 權限收緊，只有自己能讀：

```bash
chmod 600 .env
```

## 第 5 步：限制網站連線來源（建議）

網站對區網開放 8081，其中**前台戰情室不用登入**。如果現場區網有不相干的設備或訪客，用防火牆限制只允許維運網段連入。網段請依現場實際情況調整：

```bash
sudo ufw allow OpenSSH
```

```bash
sudo ufw allow from 192.168.50.0/24 to any port 8081 proto tcp
```

```bash
sudo ufw enable
```

⚠️ 一定要**先**加 `OpenSSH` 那條規則，再執行 `ufw enable`，不然 SSH 會被擋掉。

另外注意：Docker 發布的 port 會繞過 ufw 的部分規則。要確認限制真的生效，就從不在允許網段的電腦試連一次。

## 第 6 步：起資料庫 → 匯入 → 起全部服務

**順序很重要**：資料要在 API 與 Collector 啟動**之前**匯入，避免邊寫邊被覆蓋。

### 6.1 只啟動資料庫

```bash
cd ~/teco/backend/deploy && docker compose up -d mariadb
```

第一次啟動會自動執行 `mariadb/init/` 裡的全部腳本（建帳號、建表、初始資料、權限 migration），大約 30 秒。等狀態變成 `healthy`：

```bash
docker compose ps
```

### 6.2 匯入設定資料

dump 裡每張表都有 `DROP TABLE` 再重建，所以會把初始資料換成開發機的設定。沒有匯出的時序表則維持初始化建立的空表，分割區是完整的。

```bash
source .env && docker compose exec -T mariadb mariadb -u root -p"$DB_ROOT_PASSWORD" teco_hvac < ~/teco_hvac_config.sql
```

確認資料有進去：

```bash
source .env && docker compose exec -T mariadb mariadb -u root -p"$DB_ROOT_PASSWORD" teco_hvac -e "SELECT COUNT(*) AS users FROM app_user; SELECT COUNT(*) AS fcu FROM device_fcu; SELECT COUNT(*) AS placements FROM device_floor_placement;"
```

### 6.3 啟動全部服務

第一次會在 VM 上編譯 API 與 Collector 的映像檔，要花幾分鐘：

```bash
docker compose up -d --build
```

## 第 7 步：驗證

1. 四個服務都是 `running`，並且 `mariadb`、`api`、`collector` 是 `healthy`：

```bash
docker compose ps
```

2. 在 VM 上確認 API 就緒：

```bash
curl -s http://localhost:8082/readyz
```

3. 打開網站，前台戰情室應該會出現：
   - **VM 還在 Default Switch（NAT）時**：只有 Windows 主機自己連得到 VM，用 Windows 主機的瀏覽器開 `http://<VM 的 IP>:8081`
     （VM 內執行 `ip -br addr` 查 IP）。區網其他電腦連不到，這是 NAT 的正常限制。
   - **也可以從 Mac 直接開**（走 Tailscale）：`http://teco-vm-tailscale:8081`，前提是 Mac 的 Tailscale 有開 MagicDNS
     （預設有）；不行就改用 VM 的 `100.x.x.x` 位址。
   - **改成 External 交換器並固定 IP 之後**（附錄 B）：區網任何電腦都用 `http://<VM 固定 IP>:8081`。
   
   打不開的話：
   - 確認 `compose.yaml` 的 `web` ports 是 `"8081:80"`，不是 `127.0.0.1:8081:80`
   - 檢查第 5 步的 ufw 規則（如果用 Tailscale 連，要允許 Tailscale 網段 `100.64.0.0/10` 連 8081）

4. 用原本的帳號登入。帳號資料已經搬過來，所以**密碼跟開發機相同**。`JWT_SIGNING_KEY` 換了，所有人都需要重新登入，這是正常的。

5. 用平台帳號打開 **系統診斷**（`/platform/diagnostics`），接著照 [`IOT_現場接通驗證手冊.md`](IOT_現場接通驗證手冊.md) 檢查三條通道。

6. 設定 VM 每日備份，見 `backend/deploy/host-setup/03-docker-context-from-mac.md` §3.5。

## 之後更新程式

在 Mac 上執行：

```bash
npm run build
```

```bash
rsync -av --delete --exclude node_modules --exclude 'bin/' --exclude 'obj/' --exclude .git --exclude 'backend/deploy/.env' --exclude 'docs/工作站主機資料.md' ./ teco-vm-tailscale:~/teco/
```

在 VM 上執行（Mac 上可以直接 `ssh teco-vm-tailscale` 進去）：

```bash
cd ~/teco/backend/deploy && docker compose up -d --build
```

注意事項：

- `--delete` 讓 VM 跟 Mac 保持一致；被 `--exclude` 的 `.env` 不會被刪掉。
- **新增的 `mariadb/init/0xx_*.sql` 不會自動套用到已經在跑的資料庫**（init 腳本只在資料庫第一次建立時執行）。每次更新時看一下有沒有新的 migration 檔，有的話手動執行：

```bash
source .env && docker compose exec -T mariadb mariadb -u root -p"$DB_ROOT_PASSWORD" < mariadb/init/0xx_新的檔案.sql
```

- 更新前先備份一次資料庫（§3.5 的指令手動執行一次即可）。

## 出問題要重來

**第一次部署失敗、想整個重建時**，下面這個指令會刪掉資料庫 volume，**資料會全部消失**，只能在還沒有正式資料時使用：

```bash
docker compose down -v
```

刪掉之後，從第 6 步重新開始。

已經有正式資料之後，不要再使用 `down -v`。要還原就用備份檔（見 §3.5 的還原指令）。

## 附錄 A：遠端連線（Mac → Windows、Mac → VM，都走 Tailscale）

離開現場區網也能連進去。下面是**已經實際連通**的做法（2026-09-29）。

### A.1 Tailscale 安裝位置

| 裝置 | 安裝方式 |
|---|---|
| Mac | `brew install --cask tailscale`，或 Mac App Store，登入後 `tailscale status` 應列出所有裝置 |
| Windows 主機 | 官方 Windows 安裝程式，登入同一個帳號 |
| Ubuntu VM | `curl -fsSL https://tailscale.com/install.sh \| sh`，再 `sudo tailscale up --hostname=teco-vm`（若要用 Tailscale SSH 加 `--ssh`），依提示網址在瀏覽器授權 |

三台都要用**同一個 Tailscale 帳號**登入。

### A.2 Windows 主機的 OpenSSH 伺服器

Windows 上的 SSH 伺服器要另外安裝（Tailscale 不能取代它，也不支援 Windows 當 Tailscale SSH 伺服器）。

- 用系統管理員 PowerShell 執行 `Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0` 時，
  **可能卡住不動**（要靠 Windows Update 下載，在現場主機上常被擋）。改用 Win32-OpenSSH 的 MSI：
  從官方 `github.com/PowerShell/Win32-OpenSSH/releases` 下載 **`OpenSSH-Win64-*.msi`**
  （不是 ARM64、也不是 Win32，先用 `$env:PROCESSOR_ARCHITECTURE` 確認是 `AMD64`），雙擊安裝。
- 啟動並設為開機自動：

```powershell
Set-Service sshd -StartupType Automatic; Start-Service sshd
```

- 登入的 Windows 帳號要**有密碼**（`net user <帳號>` 看「需要密碼」），沒有密碼的帳號預設不允許遠端登入。
- 公鑰放的位置看帳號身分：**系統管理員**放 `C:\ProgramData\ssh\administrators_authorized_keys`，
  並且**必須**收緊權限，否則會被忽略：

```powershell
icacls.exe C:\ProgramData\ssh\administrators_authorized_keys /inheritance:r /grant "Administrators:F" /grant "SYSTEM:F"
```

  一般使用者放 `C:\Users\<帳號>\.ssh\authorized_keys`。
- 登入後預設殼層是 cmd（`ls` 會報找不到），要 PowerShell 就輸入 `powershell`，或在**系統管理員 PowerShell** 執行：

```powershell
New-ItemProperty -Path "HKLM:\SOFTWARE\OpenSSH" -Name DefaultShell -Value "C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe" -PropertyType String -Force
```

- **確認金鑰登入成功之後**，才把 `C:\ProgramData\ssh\sshd_config` 的 `PasswordAuthentication` 改成 `no`
  （改之前先 `Copy-Item` 備份，改完用 `& 'C:\Program Files\OpenSSH\sshd.exe' -t` 檢查語法再 `Restart-Service sshd`，
  並保留一個已連線的視窗，新視窗驗證成功再關）。

### A.3 Mac 的專用金鑰與 `~/.ssh/config`

產生只給這個專案用的金鑰（設定 passphrase）：

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_teco -C "teco-hvac-mac"
```

`~/.ssh/config`（`HostName` 換成 `tailscale status` 顯示的 `100.x.x.x`；VM 使用者換成你安裝 Ubuntu 時建立的）：

```
Host teco-win-tailscale
    HostName <Windows 的 Tailscale 位址>
    User <Windows 帳號>
    IdentityFile ~/.ssh/id_ed25519_teco
    IdentitiesOnly yes

Host teco-vm-tailscale
    HostName <VM 的 Tailscale 位址>
    User <VM 使用者>
    IdentityFile ~/.ssh/id_ed25519_teco
    IdentitiesOnly yes
```

把公鑰放到 VM（剛裝好時還接受密碼，第一次用密碼放）：

```bash
ssh-copy-id -i ~/.ssh/id_ed25519_teco.pub teco-vm-tailscale
```

Windows 那台則照 A.2 手動貼到 `administrators_authorized_keys`。確認是金鑰登入（不是密碼）：

```bash
ssh -v teco-vm-tailscale 2>&1 | grep -E "Authenticated"
```

### A.4 一定要做的收尾

- **關閉 Tailscale 金鑰到期**：裝置金鑰預設約 180 天到期，到期後會被踢出網路，遠端就連不進去了。
  到 Tailscale 管理後台的機器列表，對 Windows 與 VM 各按 `...` → **Disable key expiry**。
- **Tailscale 帳號歸屬**：免費 Personal 方案限非商業用途（依官方定價頁，2026-09-29 查詢；
  6 位使用者、Tailscale SSH 5 台主機，裝置數不限）。目前裝置登記在個人 GitHub 帳號底下，
  **正式維運前要改成客戶或公司名下的帳號**，不然交機後這條通往客戶內網的入口會留在個人帳號裡。
  客戶主機上安裝遠端存取軟體也要先取得客戶同意。
- 想限制只有特定裝置能連進現場主機，到 Tailscale 管理後台設定存取規則（ACL），預設同帳號下的裝置全部互通。

### A.5 連不進去時的排查

| 現象 | 可能原因 |
|---|---|
| `ping` Tailscale 位址不通 | Mac 的 Tailscale 沒登入（`tailscale status` 顯示 Logged out）；或 Windows 防火牆擋 ICMP，改用 `tailscale ping <位址>` 測 |
| `Connection refused`（Windows） | `sshd` 服務沒啟動，`Get-Service sshd` |
| `Connection refused`（VM） | Ubuntu Desktop 沒裝 SSH 伺服器，見第 1 步 |
| `Permission denied (publickey)` | 公鑰沒放對位置；Windows 系統管理員要放 `administrators_authorized_keys` 且要跑 `icacls` |
| 一直要求輸入密碼 | 同上，`ssh -v` 看是不是在「Offering public key」後被拒絕 |
| 隔幾個月突然全部斷線 | Tailscale 金鑰到期，見 A.4；只能靠 AnyDesk 進 Windows 重新登入 Tailscale |

## 附錄 B：改成 External 交換器並固定 IP（接設備、讓區網看得到網站前必做）

### B.1 為什麼要改，以及為什麼現在不能在 VM 裡直接設固定 IP

目前 VM 掛在 Hyper-V 的 **Default Switch**（Internal，NAT）：

- 網段（例如 `172.17.160.0/20`）由 Windows **每次開機時自動挑選，重開機後可能改變**。
  如果在 VM 的網路設定裡把 IP 手動固定成目前的位址，Windows 重開機後 VM 的位址就落在錯誤網段，
  閘道、DNS 都是舊的，**VM 會完全沒有網路（連 Tailscale 也一起斷）**。所以在 Default Switch 上**不要**設固定 IP。
- VM 在 NAT 後面，**不在現場設備網段（`192.168.10.x`）**，Collector 連設備要靠 Windows 主機的 NAT 轉送，
  能不能通沒有保證；區網其他電腦也連不到 VM 上的網站。

External 交換器會把 VM 接到跟 Windows 主機一樣的實體網段，VM 就是區網裡的一台正常主機，才能固定 IP、
連設備、讓其他電腦開網站。

### B.2 做之前先確認（很重要）

這一步會讓 Windows 主機的網路**短暫中斷**，主機的 IP 設定也會重新套用到新的虛擬網卡上。
**不要透過 SSH 操作**——用 **AnyDesk 或 Hyper-V 主控台**，並且：

1. 記錄現況（截圖或複製）：

```powershell
ipconfig /all
```

```powershell
Get-NetAdapter | Where-Object Status -eq 'Up' | Select-Object Name, InterfaceDescription, MacAddress, LinkSpeed
```

2. 確認**哪一張網卡**接現場網段。文件記載現場主機是雙網段（主 `192.168.50.199`、進階 `192.168.10.199`），
   可能是同一張網卡設兩個 IP，也可能是兩張網卡——**要先弄清楚**，否則會把錯的網卡綁進交換器。
   無線網卡不適合綁 External 交換器。
3. 向現場網管確認：
   - VM 要用的固定 IP（設備網段內、沒有被別台使用，例如 `192.168.10.200`）
   - **這個網段的閘道與 DNS**（有沒有、是誰）
   - **VM 上網的路徑**：Tailscale、`docker compose build`（下載套件）、`apt` 都需要 VM 能連外網。
     如果現場設備網段（`192.168.10.x`）沒有連外路由，上網要走另一個網段（例如 `192.168.50.x` 的路由器），
     那 VM 需要**兩個位址**（見 B.5）。

### B.3 Windows：建立 External 交換器並改接 VM

網卡名稱換成 B.2 查到、接現場網段的那張（例如 `Ethernet`）。`-AllowManagementOS $true` 讓 Windows 主機自己
也能繼續透過這張網卡上網：

```powershell
New-VMSwitch -Name "Teco-Field-Switch" -NetAdapterName "<網卡名稱>" -AllowManagementOS $true
```

建完後主機網路會短暫斷線再恢復。**立刻驗證主機網路與 Tailscale 還在**：

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Select-Object InterfaceAlias, IPAddress, PrefixLength
```

```powershell
Test-NetConnection www.microsoft.com -Port 443
```

主機原本的 IP（例如 `192.168.50.199`、`192.168.10.199`）應該轉移到 `vEthernet (Teco-Field-Switch)` 上。
如果 IP 掉了，用 AnyDesk 手動補回，並對照 B.2 記錄的 `ipconfig /all`。

把 VM 的網卡接到新交換器（VM 名稱依實際，本專案是 `teco_iot_area`）：

```powershell
Connect-VMNetworkAdapter -VMName teco_iot_area -SwitchName "Teco-Field-Switch"
```

### B.4 VM：設定固定 IP（在 Hyper-V 主控台操作，不要用 SSH）

切換交換器後 VM 會暫時失去網路，Tailscale 需要重新連線，所以**用 Hyper-V 主控台**（或 AnyDesk 看主控台）操作。

先看網路連線的名稱：

```bash
nmcli connection show
```

Ubuntu Desktop 的有線連線通常叫 `Wired connection 1`。**只有一個位址的情況**（設備網段本身有閘道且能上網）：

```bash
sudo nmcli connection modify "Wired connection 1" ipv4.method manual ipv4.addresses 192.168.10.200/24 ipv4.gateway <閘道> ipv4.dns "<DNS>"
```

```bash
sudo nmcli connection up "Wired connection 1"
```

（用圖形介面也可以：Settings → Network → 有線連線齒輪 → IPv4 → Manual，欄位對應上面的位址、Netmask、Gateway、DNS。）

⚠️ 設定前先確認 `192.168.10.200` 沒被別台使用：從另一台在同網段的電腦 `ping` 它，**沒有回應**才代表可用。

### B.5 現場設備網段沒有連外時：VM 兩個位址

如果上網要走另一個網段的路由器（例如主網段 `192.168.50.0/24`，閘道 `192.168.50.1`），可以讓 VM 同一張網卡同時有兩個位址，
**預設閘道指向能上網的那個網段**，設備網段是直連的不需要閘道：

```bash
sudo nmcli connection modify "Wired connection 1" ipv4.method manual ipv4.addresses "192.168.10.200/24,192.168.50.200/24" ipv4.gateway 192.168.50.1 ipv4.dns "<DNS>"
```

```bash
sudo nmcli connection up "Wired connection 1"
```

以上位址與閘道都是**範例**，以 B.2 向現場網管確認的為準。


```bash

```


```bash

```

```bash

```


- 三台設備都 ping 得到（設備若擋 ICMP，改用 `nc -vz -w 3 <IP> <Port>` 測 Modbus 埠，見 `IOT_現場接通驗證手冊.md` 第 1 層）
- 能連外，Tailscale 是連線狀態，Mac 的 `ssh teco-vm-tailscale` 仍然可以連進來

VM 網卡改接後要更新的地方：`compose.yaml` 的 `Collector__*` 位址不用改（Collector 走 VM 的網路直接連設備）；
第 5 步的 ufw 規則要確認允許的網段包含實際使用網站的網段。

### B.7 出問題要退回去

用 AnyDesk 或 Hyper-V 主控台把 VM 接回 Default Switch，並把 IP 改回自動取得：

```powershell
Connect-VMNetworkAdapter -VMName teco_iot_area -SwitchName "Default Switch"
```

```bash
sudo nmcli connection modify "Wired connection 1" ipv4.method auto ipv4.addresses "" ipv4.gateway "" ipv4.dns ""
```

```bash
sudo nmcli connection up "Wired connection 1"
```

Windows 主機如果因為 External 交換器造成網路異常，可以移除交換器讓主機網卡回到原本設定
（**先確認沒有 VM 還接在上面**）：

```powershell
Remove-VMSwitch -Name "Teco-Field-Switch"
```

移除後若主機的 IP 設定沒有自動恢復，照 B.2 記錄的 `ipconfig /all` 手動還原。
