# B1 底圖換版計畫：改用 CLUB-M 原始 CAD SVG

**目標：** 把 `/admin/floor-plan` 的設備擺放示意圖，從目前手工簡化的 29 個分區（`floor-plan.ts` 內寫死的多邊形），換成 `CLUB-M IF B1 (精簡版)-reset.svg` 的真實建築底圖，重新定義分區編號，並讓 2D SVG 與 Three.js 3D 共用新座標。

**結論：可行，已全數完成並上線（2026-09-10）。** 該 SVG 不只是一張圖，裡面藏有可直接轉成互動分區的 CAD 圖層資料。三個決策點已定案，`/admin/floor-plan` 現在使用新底圖與 32 個分區，並新增 B1／B2 樓層切換 UI（B2 暫代用 B1 幾何）。

### 3. 圖面有 3 份副本，已解出對位關係

同一套圖層在圖面上有 3 份：

- **A 副本**：與可見底圖對齊（x 26–774, y −76–569）← 我們要用的
- **B 副本**：`A + (2338, −199)`（**實測誤差 < 1 單位**），標註文字都在這裡
- **C 副本**：A 旋轉 180°（文字 transform 為 `matrix(-1 0 0 -1 …)`）

把 B 副本的文字平移回 A 座標後，取得真實用途名稱：
**家樂福、雄獅旅遊、工紡、餐廳、打擊區、教室、開放打擊區、VIP區、B100/B101/B1017/B1020/B1021、1F梯廳、1F燕窩**，以及各支管容量（61.5RT / 41RT / 37RT / 29.5RT / 22RT / 21RT / 18.5RT / 14RT）。

> 這些是「冰水支管服務對象」的標註，不是房間門牌，可作為命名依據但**須業主確認**。

### 4. 已知的幾何瑕疵（實測，Phase 0 已全數處理）

- **底圖被裁切**：`_隔間區分` 範圍到 (774, −76)，可見底圖只到 (712, 543)。上方與右側的分區**沒有建築細節**——那塊在「精簡版」被刪掉，無法從本檔還原。已改用同一份圖的 `_大樑` 結構線補上，缺圖區不再是空白。
- **6 個巢狀多邊形**（外框包住內室，例如 B1-Z16 內含 Z11/Z14/Z15/Z17/Z22）。相鄰分區共用牆線，用頂點判斷包含關係不可靠，已改為內部取樣（≥90% 命中才算包含）。`placementArea()` 需改成取「最小的包含分區」。
- **1 個自相交多邊形**：成因是 CAD 匯出的重複收尾點，去重後即消失，`THREE.ExtrudeGeometry` 的 earcut 可正常三角化。
- **多邊形頂點數 4–35**，含 L 形與弧邊 → 標籤點改用 pole-of-inaccessibility，不用 bbox 中心。
- **7 個 `rect` 分區**：早期用 Python 快篩時因為只取了矩形對角兩點而被漏掉，實際分區數是 **32 不是 26**。

## 二、決策點（已定案 2026-09-10）

1. **底圖裁切**：不另外要求重新輸出。改由 `_大樑` 結構線補上缺圖區，並在資料上以 `baseCoverage` 標記每個分區的底圖覆蓋率（0 = 完全沒有建築細節）。
   - 完全沒有底圖：B1-Z01、B1-Z04、B1-Z30（3 個）
   - 部分超出底圖：10 個
2. **分區編號規則**：採 `B1-Z01 … B1-Z32`，依圖面由上而下、由左而右編號；中文名稱獨立成 `name` 欄位，目前留空待業主確認，圖面上的冰水／空調標註原文放在 `notes` 供對照。
3. **比例尺**：不標註。圖面無尺寸資訊，設備尺寸一律視為示意，已寫進產生檔的檔頭註解。

已完成的幾何清理：去重收尾點（消除自相交）、移除共線頂點、面積 < 200 圖面單位² 的 CAD 碎片濾除、內部取樣判斷巢狀關係、pole-of-inaccessibility 算標籤點、B 副本標註平移 `(−2338, +199)` 回 A 後落點對應到分區。

`--rotate180` 可一次把座標與底圖都轉 180°，方位若要改用那個方向，重跑一次即可，不需要在執行期做 transform。

**底圖用 `<image>` 引用，不要 inline 進 DOM。** 14,364 個節點 inline 會拖垮 SVG 事件與 3D 頁面；當成圖片可走瀏覽器快取。已驗證 Astro dev 可正常提供並在瀏覽器渲染。

**風險與已知限制**
- 13 個分區的建築細節只能靠結構線示意，配置精度受限（已用 `baseCoverage`／`partialBase` 在資料與 UI 上揭露）

- **B2 暫時完全沿用 B1 的幾何與底圖**：分區形狀、面積、標註都是 B1 的資料，B2 的實際格局可能完全不同；`isFloorPlanPlaceholder()` 已在多處 UI 明示，但仍需業主知悉這只是「有得操作」而非「B2 的真實圖面」
